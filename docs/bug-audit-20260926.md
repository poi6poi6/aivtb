## 1. P1：默认模式下 WebSocket 缺少来源和管理权限校验

位置：`brain/webui.py:143–161`、`brain/webui.py:484–492`、消息分发中的 `memory_manage` 和模式控制分支。

默认 `public_test=false` 时，中间件直接放行；Origin 校验仅在朋友测试模式执行。`/ws` 本身也不验证来源，只有注入事件的 `owner_control` 会按来源计算，其他管理消息不检查该标记。

已使用带 `Origin: https://unrelated.example` 的本机 WebSocket 连接复现：握手成功，能够读取并删除夹具中的普通记忆、切换手动模式。服务端没有把异源连接与本机主控区分开。是否能由特定浏览器的外部网页直接发起连接还受浏览器网络策略影响，本次未进行真实浏览器攻击演练。

建议在 WebSocket 握手前统一验证本机 Host、来源和授权，并对管理消息单独检查控制权限；保留 OBS 合法来源的明确规则。

## 2. P2：Windows 音频接口可以读取配置目录外的 WAV

位置：`brain/webui.py:466–471`。

接口直接把 URL 中的文件名拼到 `audio_dir`，只检查 `.wav` 后缀和文件存在。Windows 会把 URL 解码后的反斜杠当作路径分隔符，因此 `/audio/..%5coutside.wav` 能跳出音频目录。

临时夹具在 `audio/` 的同级目录放置 `outside.wav`，实际 HTTP 返回 200 和该文件的全部内容。影响范围是进程可读的其他 WAV 文件，并非所有文件格式；朋友测试模式的登录校验也不能代替文件路径边界检查。

建议先解析目标绝对路径，验证其位于配置的音频根目录内，并拒绝分隔符、绝对路径等非文件名输入。

## 3. P2：失败的代码测试可被部分重跑覆盖，审核误报“可应用”

位置：`brain/code_review.py:104–115`。

测试结果仅按命令中的第一个测试目标去重。实际复现：

1. `python -m unittest tests.test_a tests.test_b`，B 失败，退出码 1。
2. 仅重跑 `python -m unittest tests.test_a`，退出码 0。
3. B 从未修好或重跑，但 `inspect()` 返回 `tests_passed=true`、`can_apply=true`。

复现运行了真实临时 unittest 进程，前后源码哈希相同。相同入口还把实际 `Ran 0 tests ... OK` 当成有效测试通过。这不会自动应用代码，但会向主播提供错误的通过状态并允许确认应用。

建议按完整测试范围判断一次成功重跑能否覆盖旧失败，并要求确实执行了测试。不能让缩小范围的成功结果清除更大范围的失败。

## 4. P2：暂停期间合成详细回复会丢掉中间语音片段

位置：`brain/persona.py:361–369`、`brain/playback.py:326–331`。

首句提前拆分后，一段四句的详细回复能产生 5 个语音片段，但默认配置只允许当前片段之外再排队 3 个。播放暂停时合成仍继续，队列溢出后删除最早的同优先级片段。

使用实际 Persona 分段和 SpeechPipeline、夹具 TTS 复现：生成 `[0,1,2,3,4]`，最后只保留 `[0,2,3,4]`；首句后半段被删除，恢复播放不会补回。合成速度持续快于播放时也可能触发。

建议对同一回复增加队列背压，或以完整回复为单位管理播放容量，不能静默删除当前回复的内部片段。

## 5. P2：连续语音的低置信度审核被后续高置信度片段覆盖

位置：`brain/static/index.html:1300–1333`，尤其 `1326–1327`。

页面拼接所有识别片段作为待发文本，却只把最后一个片段的候选和置信度传给 `voiceDecision`。

真实页面处理函数的测试环境复现：先收到置信度 0.4 的“我明天十点出门”，页面要求核对；随后追加置信度 0.95 的“请帮我记住”，审核提示被覆盖，开始自动发送倒计时，最后把包含前面不确定时间的整段文字发出。

建议保留每个未确认片段的置信度和歧义状态，任何待审核片段存在时都禁止整段自动发送，直到用户确认或修改。

## 6. P2：同名不同账号共用人格关系偏好

位置：`brain/personality_evolution.py:315–321`、`brain/personality_evolution.py:651–665`。

长期事实记忆虽已有账号隔离，人格关系仍以昵称 `event.user` 为键，没有使用 `source` 和 `viewer_key`。

临时状态复现：账号 A 两次表示偏好倾听后，同名但不同 UID 的账号 B 收到完全相同的关系上下文，也被认定“反复表现出更偏好先被倾听”。信任、熟悉度和上一轮回复的反馈归属也使用这个昵称键。

建议统一以平台与稳定账号标识存储关系，仅把昵称用于展示；旧昵称记录不能自动认领到任意同名账号。

## 7. P2（需开启导演）：观众投票后仍可能被判断为无人回应

位置：`brain/main.py:318–329`。

投票命令计数后立即 `continue`，跳过后面的 `director.observe_event()`。因此有效参与不会更新导演的活跃观众、弹幕热度或等待回答状态。

使用实际事件接入函数、LivePolls 和 LiveDirector 复现：3 票正常入库，但导演活跃人数仍为 0、仍等待回应；30 秒后生成“刚才的问题暂时没人接”的转场提示。

当前 `config/settings.yaml` 中导演关闭，所以该问题在开启导演并由其组织互动时才出现。建议成功投票时同步导演的参与统计和相关问题状态，同时保持投票不逐条触发模型回答。
