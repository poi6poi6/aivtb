# 直播优化记录 · 2026-09-27

本轮落实观众身份、后台健康、写盘与网页发送、投票绘画衔接、跨场栏目记录及音频保留六项优化。

## 入口与操作

- 主控新增 **栏目手记**（`/shows`）；投票页的已结束投票可生成绘画委托。
- 在手记创建本场，检查并编辑绘画要求，保存卡片后提交草稿。平票和零票由主播选定选项；不会自动决定。
- 已有绘画仍通过原画布修改与确认上色。卡片可记录命名、备注和下次待办。
- 收播生成事实回顾，下场可接续待办。历史作品按当场确认的版本查看；沿用旧投票会明确标注来源。
- 设置区新增 **运行状态与音频收藏**（`/runtime`）：显示后台任务、保存状态、任务服务连接、首音等 P95 耗时，以及最近 100 段临时语音的试听和收藏。

## 身份与保存

来访计数、兴趣反馈和人格关系统一使用来源与账号标识。相同昵称的不同账号不再共享“老粉”提示；账号改名仍沿用同一记录。本地文字与语音按本地身份关联。旧昵称档案只迁移到本地归属，不推断它属于某个平台账号。实际数据在服务正常加载与保存时迁移，本次验证使用临时数据。

四类 JSON 状态在主服务内按 250 毫秒窗口合并写入。单写者将一致快照在线程中序列化、刷新并原子替换；写入失败保留待保存版本、报告状态并重试。人工新增、修改与遗忘记忆等待落盘；正常退出排空待保存数据。突然断电仍可能丢失尚未落盘的短窗口更新。

同步脚本与未启用后台写入的调用仍保持同步原子写入行为；事件日志继续采用追加写入。

## 后台运行与网页发送

命名工作任务会记录运行、恢复等待、失败及停止状态。弹幕摄入、维护等可恢复任务最多重试三次并退避；语音管线、游戏控制及部分外部制作任务停止后需要检查并重启主服务，避免重启已关闭的对象或重复操作。关键任务失败、持久化失败或任务服务断连会使健康状态显示未就绪。音频整理故障作为扩展告警保留，刷新列表不会掩盖错误。

每个网页连接使用独立、有界的发送队列。连续的状态快照可合并；音频、控制及聊天消息保持顺序。发送超过两秒或可靠消息队列溢出时断开该慢连接，执行正常播放器断线处理，由前端重连。新增事件循环延迟指标，与既有首字、首句、首音、TTS 指标一同用于实际对照。

健康状态描述应用工作任务，不等同于真实模型、声卡或 OBS 的完整链路验收。

## 音频保留

默认每五分钟整理一次，保留七天、容量上限 1024 MiB，可在 `config/settings.yaml` 的 `tts.audio_retention_*` 配置调整或关闭。

只处理音频目录顶层符合现有 TTS 命名格式的 WAV。保护收藏、参考、播放中、队列内、等待入队的合成结果和最近五分钟的新文件；不递归处理试听子目录，不跟随符号链接或 Windows reparse 路径，不删除硬链接。保护文件超过容量时不会为达到上限强删。

收藏清单持久化在音频目录中。目录身份变化、清单损坏或维护失败时停止清理并显示状态。运行状态与收藏管理接口仅供本机主播，朋友测试模式不能访问。
