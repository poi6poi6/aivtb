# B 站自主活动（2026-10-26）

主控制台的“B站自主活动”也可通过本机 `/bilibili-activity` 打开。当前负责主人格的同一个 LLM 根据角色兴趣搜索视频，阅读简介、可取得的字幕和热评，保存见闻、公开阅读日记、动态草稿与互动建议。宿主根据已保存的设置，通过正常登录的浏览器发布动态、点赞或评论。

这次参考了 `dsh-bili-scroll`、`dsh-bili-interact`、`dsh-bili-whale` 的阅读、互动和日记能力，并适配现有主人格、宿主调度和浏览器助手；没有完整安装这三个上游包，也没有引入它们的独立人格或调度器。没有接入视频画面识别、音频转录、投币、收藏、关注或私信监听。

读取字幕不等于看完视频。当前只读取第一 P 的一个可用字幕轨，优先中文，最多 12,000 字、2,000 条字幕；达到限制会标明截断。热评最多 10 条，是其他用户的观点，不能当作视频内容事实。只有标题时不记录观看内容。

## 启用

1. 在项目的 `tools/deepseek-harness` 运行 `npm ci --ignore-scripts --no-audit --no-fund` 安装固定依赖，要求 Node.js 22.19+（22.x）或 24+。当前工作区已安装，并保存 package-lock.json；官方 SDK 与 Harness 固定为 `0.2.1-rc.2`，隔离于现有 OMP／Astra 路径。活动决策直接复用已实例化的主人格 LLM：当前 `persona_llm.backend: inherit` 继承 `llm.deepseek-flash`（官方当前对应 V4.1-Flash-1017），沿用已有 DeepSeek 密钥和调用参数，不需要额外配置，也不会在主人格不可用时切换模型。
2. 在 Chrome／Edge 重新加载 `tools/bilibili-browser-extension`，或下载新版助手 ZIP 后覆盖原扩展目录再重新加载，确认版本为 `1.2.0`，再刷新活动页。新版增加固定的只读视频 API 与字幕文件域名权限；仅显示浏览器已连接不能证明旧扩展已经升级。
3. 重启主控，从本机控制台打开“B站自主活动”，保持该页面打开。扩展沿用同一浏览器的正常登录状态；登录及验证需要在 B 站页面完成，不读取或导出 Cookie。
4. 点击读取账号，核对 B 站 UID。先使用“立即逛一次”查看见闻、日记、草稿和互动建议。自主浏览、自主发布、自动点赞和自动评论默认全部关闭。
5. 按需要保存浏览间隔、单轮数量、活动时段和每日额度，再开启相应开关。手动浏览不要求开启自主浏览；手动发布不要求开启自主发布，但同样核对 UID 和每日发布额度。点赞和评论的开关同时授权每轮结束后的自动执行，不能把它们当作仅允许手动操作的开关。

缺少运行依赖、浏览器助手、有效登录或可读页面时，会显示未就绪或失败。关闭活动页面后不能继续执行新的浏览器动作；浏览器回执超时会停止本轮，不能用反复提交绕过验证。

## 对话与自主活动

自主浏览由主控的空闲状态触发。活动时段按 UTC+8 计算，默认 0–24 点全天；可设置跨午夜时段，开始与结束不能相同。文字或语音聊天会取消正在进行的浏览，至少留出 90 秒再考虑下一轮；正在说话、播放音频、点歌或占用桌面控制时也不自动开始浏览。

见闻和日记存储在 `data/bilibili-activity.json`。见闻记录来源、阅读证据、摘要及当时感想；日记必须引用本轮已保存的公开见闻。“公开”是可供对话召回的标记，保存日记不会向 B 站发动态。它们不会直接修改角色卡、人格特质或观众事实。

网页文字／语音聊天和已接入的 QQ 对话会按当前话题召回相关见闻或日记，也能回答“今天读了什么”这类时间问题。最多加入 3 条、总计 3,500 字的召回上下文，不把整个存储塞进聊天。QQ 群聊只接收明确标为 `public` 的记录；本机及私人陪伴聊天可兼容旧版未标记的见闻。没有相关内容就不注入。

Harness 使用单独会话，仅开放六个工具：`bili_search`、`bili_read`、`bili_note`、`bili_draft`、`bili_diary`、`bili_interaction`。每一步由当前主人格模型返回结构化决策，再由宿主校验并交给 Harness 执行。模型连接与日常对话共用，活动消息记录单独保存于本次临时会话，不会读取私人聊天、占用对话话题或进入口播队列。角色卡与公开阅读结果构成活动上下文，记录仍由宿主确认后保存。

读取地址必须来自本轮搜索；草稿和互动建议必须来自本轮实际读取，日记必须引用本轮已记见闻。网页不能扩展工具权限。每轮时间、模型步骤、工具次数和阅读数量都有上限，每轮最多保存一条动态草稿、一篇日记和一条互动建议。取消活动会停止本轮模型请求，不关闭日常聊天共用的连接；模型出错或返回无效决策时停止，不使用聊天占位回复当作工具指令。密钥留在原人格连接中，不传入 Harness 子进程。

活动页会显示证据类型：`full_subtitles` 是已取得字幕轨在当前第一 P 范围内的完整文本；`subtitle_excerpt` 是截断片段；`visible_subtitles` 只代表页面当时显示的字幕；`page_metadata` 只代表简介等页面资料。扩展通过固定 API 获取视频资料、字幕地址和热评，不读取或导出 Cookie。接口不可用时保留已取得的页面证据，不伪造完整字幕；风控或超时后不循环重试。

## 点赞与评论

模型的 `bili_interaction` 只保存 `draft` 建议，不直接点击。建议只能是 `like` 或 `comment`，评论正文最多 500 字。宿主在本轮结束、仍空闲且设置未变化时，才按已保存的“允许自动点赞”／“允许自动评论”开关执行对应建议。开关要求指定 UID，默认关闭；手动点击建议卡的执行按钮也受同一开关、账号和额度限制。

点赞与评论共用每日互动额度，默认 3 次，可设 0–10；0 表示不执行，额度按 UTC+8 自然日计算，结果未知也占用额度。动态发布使用独立的每日发布额度。宿主和扩展都会先持久保存本次尝试，再执行提交；同一账号、视频和动作不重复创建或发送。账号变化、编辑器已有正文／附件或页面结构无法确认时停止。

已点赞的视频不会再次点击而取消点赞。评论必须得到相符的作者、完整正文、真实评论 ID 和提交时间证据，才能确认为 `completed`；有歧义则保持 `unknown`。已确认评论可使用保存的评论 ID 再次核验。`executing` 表示发送中；断线、取消、超时或重启后的未确认尝试转为 `unknown`，活动页只提供核验，不提供重发。核验不会再点击点赞或发送评论。

## 发布与结果核验

发布由 Python 主控发起，不是模型直接点击任意网页。主控先核对设置的 UID 和浏览器当前账号，动态正文固定后才交给扩展。草稿生成后变更了已有目标账号，需要重新生成草稿。

发布前先持久保存“正在发布”和本次额度占用；扩展先检查本人动态列表是否已有同文，再填入正文。只有得到相符的账号、完整正文、发布时间证据及真实动态 ID／链接才显示“已发布”，作者身份还要在详情页单独确认。扩展同样按请求和草稿标识保存一次提交屏障，不能反复点击发布。

发布期间断线、取消、进程重启或没有可靠回执，会留下“结果未知”。此时只能核验，不能重发；核验可以按已知动态链接，或本人动态页唯一且符合提交时间的正文候选确认，无法唯一确认就继续保留未知。若重装扩展丢失提交时间，且宿主没有已确认的动态链接，则保留未知，需要人工检查原账号。未知结果也计入当日发布额度，防止断线触发重复发布。每日额度按 UTC+8 的自然日计算。

停止活动会先取消宿主与浏览器后续步骤，再保存关闭状态；写盘失败也会停止运行，并锁住新操作等待修复。停止不能撤回已经发往 B 站的提交，也不会自动删除已发布动态。用户可在正常 B 站页面管理已发布内容。

## 本机边界与验证

活动接口只接受本机访问，写入要求严格同源。朋友测试／公网模式不可访问该功能。原有点歌协议与播放流程独立保留。

状态有数量上限：200 条见闻、100 篇日记、100 条草稿／动态凭证、200 条互动建议／凭证和 200 条活动日志。新建草稿时可清理已丢弃且从未提交的草稿；发布与互动凭证不会为了腾位置被自动删除，记录满额后停止新增对应记录并显示原因。损坏的存储文件会停止执行而不是重建一份空记录。日志不包含密钥或浏览器登录凭据。

测试覆盖宿主与浏览器桥、来源约束、账号不符、提交前持久化、断线和重启后的未知状态、重复回执、真实链接校验、聊天暂停，以及 UI 与扩展的离线流程。离线测试不能替代真实 B 站账号页面验收；本次没有向外部账号发布测试动态。

`tools/deepseek-harness/verify-persona.py` 验证实际 Python → 官方 SDK → 主人格接口 → 活动宿主完整链路：7 次本地替身模型决策、6 个工具调用，保存见闻、动态草稿、日记和未执行的互动建议。浏览器和模型均为替身，没有外部操作。`verify-persona.mjs` 验证官方 provider 扩展接口，主人格模式禁用 DeepSeek provider，子进程不带模型密钥。

离线验证入口包括 `tests/test_bilibili_activity.py`、`tests/test_bilibili_experience.py`、`tests/test_bilibili_activity_ui.js`、`tests/test_bilibili_activity_reader.js`、`tests/test_bilibili_interaction_extension.js` 及原有浏览器助手测试。2026-10-23 首版回归记录保留于 `data/validation/bilibili-activity-20261023-*.log` 和 `data/validation/bilibili-persona-20261023-*.log`，不能作为本次新增能力的真实账号验收。本次需重启主服务、重新加载助手 1.2.0 并刷新活动页才能完整生效。
