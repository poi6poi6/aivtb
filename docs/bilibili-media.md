# 本地点歌与B站点播

## B站浏览器助手安装

给定 BV 号或官方视频链接时，直接使用官方播放器，不需要浏览器助手。按歌名搜索时通过浏览器扩展读取正常 B站页面上的公开结果：匿名搜索接口在本机反复返回 HTTP 412，当前不再自动请求该接口。此功能与直播间弹幕无关，不需要开启 `sources.bilibili_enabled`。

1. 在 Chrome 或 Edge 打开本机控制台；点歌协议仍为 **6**。当前助手为 **1.3.0**；升级项目以使用新增字幕评价能力时还需重启主服务。
2. 打开控制台“B站点歌”里的安装说明，下载并解压助手 ZIP；也可直接使用项目目录 `tools/bilibili-browser-extension`。
3. 在 `chrome://extensions` 或 `edge://extensions` 开启开发者模式，点击“加载已解压的扩展程序”，选择直接包含 `manifest.json` 的目录。
4. 在同一个浏览器中按 Ctrl+F5 刷新控制台，点击“连接浏览器助手”，成功后输入点歌请求。

助手只支持本机 `http://127.0.0.1:端口` / `http://localhost:端口` 控制台，会创建并复用自己的普通 B站标签页。登录和验证由用户在 B站页面完成；扩展不读取或导出 cookie，不绕过验证，不修改用户原有 B站标签页。自己的查询标签页保持静音并暂停媒体，避免角色介绍前出声。遇到验证或访问失败，处理完 B站页面后回控制台重新发起点歌。

当前助手版本为 **1.3.0 字幕评价版**，保留原点歌协议、播放量诊断与自主活动。已安装旧版时，须将新版 ZIP 解压覆盖到之前加载的扩展目录，在扩展管理页重新加载助手，再刷新控制台并连接；确认连接状态显示 1.3.0。若直接加载项目中的 `tools/bilibili-browser-extension`，重新加载该扩展即可。只刷新网页不会更新扩展。自主活动步骤见 [自主活动说明](bilibili-activity.md)；下文的 1.0.4 诊断更新记录仅指原点歌功能。远程公开测试模式不提供此功能。

1.2.0 的新能力位于独立的 `/bilibili-activity` 页面：固定只读 API 获取第一 P 字幕及最多 10 条热评，字幕最多 12,000 字并标注完整／截断范围；保存见闻、公开阅读日记、动态草稿和点赞／评论建议。日记可在网页及 QQ 对话中按话题召回，群聊仅使用明确公开的记录。点赞／评论默认关闭，保存开启后允许宿主在空闲的每轮结束时自动执行建议，每日互动总额度为 0–10（默认 3），作息与额度按 UTC+8 计算，结果未知时只核验不重发。扩展不读取或导出 Cookie，也没有视频画面理解、收藏、关注或私信监听。此通道不改变下文的点歌搜索、选播和播放回执规则。

若搜索后没有打开 B站标签页，或只出现空白页，面板会显示失败步骤和固定原因。1.0.2 修复浏览器定时器的调用上下文，以及旧请求清理异常可能丢失结果、阻断新请求的问题；未知异常不再全部标为“准备浏览器查询”。错误不会直接归因于 IndexTTS 或 B站访问限制。真实浏览器仍需更新助手后验证；BV 直接播放不经过这条查询流程。

B站请求转交后只打开 B站面板，不再展开本地点歌面板或留下“正在交给B站播放器处理”的等待状态；没有本地音频源时隐藏空播放器。

若“找到了结果”却没有自动播放，应区分统计未读到、部分统计缺失和近似数值无法排名。`missing_play_count` 表示全部结果都没有可解析播放量，不能解释成“这些视频播放量不足”。界面按全部有效结果统计缺失数量，并说明只展示前 12 条时的总数。助手 1.0.3 增加播放统计的语义标记与字符格式兼容，在卡片出现后为延迟统计留出短暂等待；最终仍未读到时保留未知值。手选结果卡片的“播放”可继续听歌，不受自动选播门槛限制，主控制台仍先介绍真实标题再播放。

**“查看 B站原始搜索页”会在新标签页打开本次关键词的官方搜索结果，不是播放视频的官方播放器。** 即使助手仍为 1.0.3，也能使用这个入口查看页面是否已经显示统计、是否需要登录或验证。若页面需要验证，请自行在正常 B站页面完成；不要用反复重启主服务或 TTS 代替检查页面。

缺少播放量时，可展开 **“播放量读取诊断”**。助手 1.0.4 仅提供最多 2 张结果卡的统计组件结构与数字，例如可见性、图标识别和数值解析状态；不会包含搜索词、视频标题、作者、cookie、页面全文或原始 SVG 路径。诊断只用于当前页面排查，不写入持久存储。旧助手 1.0.3 不提供这份诊断：先按安装步骤更新并确认版本；已确认 1.0.4 后，应结合原始搜索页与诊断判断缺失位置，不再循环执行“更新后重试”。没有读到统计时仍保留手选，不把未知播放量当作零。

1.0.4 增加的是定位依据，尚不能据此认定用户当前页面的播放量识别问题已经修好，也不代表真实浏览器搜索或试听已通过。

## 点播后的字幕评价（1.3.0）

主控制台选择视频后，播放器旁会尝试读取当前 BV 与当前分P的字幕。读取只取得公开文字，不调用模型、不播放旁白，也不自动点赞或发评论。浏览器助手须支持 `video_subtitles_v1`，1.2.0 及更早版本会明确提示升级；没有助手时，BV直接点播仍可使用。

看完后点击 **「听她评价」**，页面先移除当前外链播放器以停止视频声音，然后让现有主人格结合字幕生成一段有具体观点和理由的评价，并使用原有音色播报。由于官方跨域播放器没有可靠的播完回执，系统不会用计时器代替你判断看完；移除播放器也不是保留进度的精确暂停。评价结束后不会自动重播视频或再次评价。

字幕最多 12,000 字、2,000 条，快照保留 10 分钟，过期可点「重新读取字幕」。完整仅指当前分P的一个字幕轨；超出限制只用前段，并在口播中说明范围。选 P2 会核对 P2 的 CID，不能取得时不会替换成 P1。没有字幕、需要登录、访问受限或读取失败时显示原因，不用简介、热评或屏幕上的零散字幕冒充字幕全文。

她只评价字幕能支持的内容；自动字幕可能误识，歌词可以讨论词句和意象，但不据此评价唱功、音色、混音、镜头或画面。输入只包含正式人设与这次公开字幕，不读取私人聊天或日记，评价不写成观众事实。

停止、换视频、新聊天、清空语音或关闭控制台会撤销进行中的评价；迟到的模型结果和音频不能恢复旧播报。独立 `/bilibili` 页面提供视频播放；读取字幕和听评价请使用主控制台。语音资源尚未就绪时会在模型调用前提示，处理后显式重试。

本次沿用已适配的字幕读取器；上游参考是 [dsh-bili-scroll 的字幕工具](https://github.com/c1overzz/dsh-bili-scroll/blob/main/vendor/bilibili-mcp/mcp_server.py) 和 [dsh-bili-whale 的字幕读取](https://github.com/Alterssss/dsh-bili-whale/blob/main/tools/commands/subtitles.mjs)。没有安装它们的独立人格、定时器或账号凭据系统。

## 点歌流程

在控制台聊天里输入 `点歌：海色`、`你好，点歌 海色`、`助手，可以帮我播放《海色》吗？` 或 `我想听海色`，她会先回应“好呀，我找找这首”，再查询曲库；确认匹配后报出歌名，等介绍语音真正播完才播放歌曲。全角/半角、大小写、空白和常见标点统一匹配；完整标题优先，部分标题只有唯一匹配时才播放，多版本会让你选择，没找到也会回应。

识别允许开头有问候、角色称呼和请求用语，但不会从任意聊天句子中抽出“点歌”就执行。`不要点歌海色`、`点歌是什么意思`、`播放《海色》是什么意思？`、`我想听你讲故事` 和 `我刚才说点歌海色` 都不会触发播放。要停止当前歌曲，请明确发送 `停止播放` 或点击停止；切歌用 `下一首`。歌名含句末语气词时可加书名号，例如 `点歌《走吧》`，以保留完整标题。

直接点击曲库里的“播放”，或切换下一首时，已经选定了歌曲，只说一句介绍再播放；加入队列不会打断当前歌曲。旁白失败或声音被浏览器拦截时，可以手动继续。换歌、停止和新聊天会取消旧旁白，迟到回执不会让歌曲突然响起。本地文件的音频仍留在当前浏览器，只把歌名用于她的介绍；服务器曲库歌曲则根据实际文件确认标题。

曲库包含 `data/songs/` 中的音频，以及当前浏览器通过“选择本地音频”添加的歌曲。后者不上传服务器，刷新或关闭页面后需要重新选择；要长期保留，可将文件放到 `data/songs/` 后点“刷新曲库”。加载尚未完成时点歌会等待结果，取消或切换请求后，迟到的结果不会突然播放。

在主控制台发送 `B站点歌 海色`、`我想在B站听海色` 或 `B站搜索 歌手`，助手会先用当前音色回应，再按播放量搜索真实视频。后台仍要求本次结果中的最高有效播放量达到 200,000（含恰好 20 万）才自动选择该版本；播放量相同时保留搜索结果中排在前面的版本。该门槛只用于后台筛选，角色回应、介绍和帮助口播均不说具体门槛，也不说“已达到门槛”。她会报出查询得到的视频标题：“这次搜到的结果里，播放量最高的是《视频标题》。来，一起听吧。”，等介绍语音真正播完，才打开官方播放器并请求有声播放。卡片仍会展示，可以改选其他版本；手选不受后台自动选择门槛限制，仍按实际标题介绍、语音播完再播放，不会冒称播放量最高。

“播放量最高”仅指本次返回且有有效播放量的候选，不代表全站或所有版本的最高值。若未满足后台门槛，她会说“这次还没找到合适的版本，你可以换个关键词，或者从结果里挑一个。”，保留卡片供手选，不播报门槛数值。缺失或无效的播放量不会当作零；如果所有结果都没有有效播放量，她会口播说明无法确认播放量，保留手选，不会编造排名或声称达到门槛。左侧 **B站点歌** 输入框使用相同流程。

请求里的动作词可以省去重复写法：`B站点歌 放个飞我去星吧` 会去掉外层点歌、“放个”和请求末尾的语气词，以 `飞我去星` 搜索，不会擅自把歌名纠正成另一首。若 `吧` 本来属于歌名，可写 `B站点歌 放个《飞我去星吧》` 保留完整标题；是否找到合适版本仍以B站真实结果为准。

直接发送 `<视频 BV 号>`、`点歌 <视频 BV 号>` 或完整的 B站视频链接，会直接点播你指定的视频，不需要助手查询，不受 20 万自动选择门槛限制，也不会换成其他视频。角色先回应，再说“就放你指定的这个视频，来一起听吧”，等介绍语音播完才打开官方播放器。界面显示“指定视频 · BV号”，不会在未读取标题时编造歌名或声称已经找到。链接中的 `p=2` 等分P信息会保留。独立页面直接打开播放器，不等待角色语音。聊天记录、嘴型和表情都使用正常角色回应流程。

如果语音合成失败、声音被浏览器拦截或旁白被跳过，不会自动抢先播放；页面提供“继续查询”或“继续播放”按钮，让你选择手动跳过回应。没查到或查询失败时，她会如实回应。新请求、停止或恢复聊天会取消旧旁白和旧查询。独立页面 `/bilibili` 使用相同的最高播放量与 20 万自动选择规则，但没有角色语音；要让她先回应和介绍，请使用页面上的“让她回应后点歌”返回主控制台。独立页面遇到最高播放量不足 20 万或全部未知时，同样说明原因并保留手选。

若提示“任务协调服务未连接”或“语音显卡授权已过期”，即使 IndexTTS 已开启，语音也还不能开始合成。请在 `启动.cmd` →“高级操作”→“启动后台任务台”恢复协调服务，再重新点歌。点歌旁白会在开始前检查资源，并显示具体原因；不会把显卡未获授权误当作已经开始回应。后台显卡任务正在运行时仍需等它完成，或在任务台主动停止该任务，不会绕过资源互斥。

播放器采用[官方外链播放器](https://player.bilibili.com/)的 `autoplay=1` 参数；浏览器限制有声自动播放时，仍需点击播放器中的播放按钮。站外播放受限时可用“在B站打开”。没有跨域播放器播放回执，页面加载不代表已经出声，界面与角色不会把请求发送成功说成播放成功。

点播本地歌曲或开始B站点歌会结束上一轮角色语音；B站点歌自身的回应仍会正常播放。新聊天、录音、“打断”或“停止播放”会停止媒体。语音清理回执只清理对应语音，不再误停刚开始的歌曲。后端的B站请求仅交给一个可见控制台，不会同时在多个标签或隐藏的OBS页面播放。角色声音在 OBS 播放页输出时，同样等该页面确认旁白播完才开视频。视频声音从当前浏览器输出，直播时需采集这个浏览器的应用音频或桌面音频。

浏览器助手的点歌通道只打开固定的官方搜索页面或指定 BV 页面，读取公开 DOM 中的视频标题、作者和播放统计。后台将结果保存为短时快照，角色介绍只读取该快照，不再向 B站发起第二次查询。请求与结果绑定查询词，过期或取消后不可继续使用；页面或助手失败不会伪装成“没有这首歌”。

页面常显示“190.9万”这类近似值。后台按显示精度保守估计上下界，只有候选的下界不低于其他候选上界且达到自动选择门槛，才声称它是本次结果中播放量最高的版本。精确数值恰好 200,000 可通过；显示“20万”无法确认实际是否达到门槛，因此保留手选。播放量相近、未知或不可靠时，也不自动编造精确排名。指定 BV 和手选不受该限制。

浏览器点歌使用协议 6，并通过 `bilibili_direct` 单独声明指定视频旁白能力。只有更新主服务代码或新版控制台明确提示旧服务能力尚未加载时，才需要重启主服务；只刷新网页不能让运行中的 Python 主服务加载新代码。历史 1.0.4 诊断更新仅涉及助手与网页，无需重启主服务或 TTS；当前 1.2.0 新增自主活动需按上方步骤更新主服务。缺少点歌旁白能力时仍提供手动继续。离线测试模式不调用真实语音或 B站服务。

若已识别的点歌请求从问题卡等入口意外进入普通聊天回复，她会说明“这条点歌还没有执行”，引导从聊天输入框或点歌面板发起；不会据此声称曲库没有歌曲。撤销语音输入或确认保存原话也不会重新执行其中的点歌。
