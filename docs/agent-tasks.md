# 助手后台任务

## 已接入的数据流

日常人设对话仍使用原有 DeepSeek/IndexTTS/Live2D 管线，自然任务表达仍由 DeepSeek 做结构化意图识别。后台任务改为独立的本机执行服务，主程序通过 TaskClient 提交命令、订阅状态与通知：

`聊天任务请求 / 8080、8085 任务台 → 8085 任务服务 → TaskService / SQLite → 权限与资源检查 → Astra 执行 → 实际产物与状态回执`

默认 `auto` 与显式 `direct` 都由宿主直接调用 Codex App Server / `gpt-6-astra`。当前已注册的每种任务都对应一个 Astra 执行契约；读取、修改和测试属于这次执行，不需要另一个模型先转述一次相同请求。

显式 `omp` 保留兼容链路：`OMP 18.1.17 / DeepSeek Flash → astra_execute → Astra`。OMP 仍只有宿主注册的单个执行工具，不是可自由组合多种工具的规划器，也不是日常对话的主会话。两条路径使用相同的套餐检查、权限、预算、取消与产物核验。Astra 的原始任务、工作目录、资源类型和执行方式由 Python 宿主固定，模型不能通过文字改写权限。

## 使用

- 主项目运行时，打开 `http://127.0.0.1:8080/tasks`，或主界面的“后台任务”。
- 独立使用：在项目目录运行 `.\启动.cmd -Action tasks-start`，打开 `http://127.0.0.1:8085/tasks`。只启动任务服务，不启动直播、Minecraft、TTS 或公网链接。
- 主程序启动时会检查并在需要时隐藏启动 8085 服务。8080 与 8085 任务台可同时打开，它们查看和操作同一个执行服务；文件锁只用于防止第二个执行器启动。
- 正常关闭主程序只解除 TaskClient 连接、释放前台资源，不取消后台任务。画图或代码任务可以继续，在 8085 查看结果；重新启动主程序可再次连接。
- `.\启动.cmd -Action tasks-stop` 取消全部待执行/执行中任务并关闭 8085 服务。任务台的“停止全部任务”只取消任务，保留服务；关闭浏览器标签页也不代表停止任务。
- 对话输入 `/任务 帮我整理……` 或“任务：……”。绘图请求可用“帮我画一张……”。自然修改、查询和取消表达先识别，再由宿主核对归属与真实状态，歧义请求不会直接执行。
- 本机同源 WebSocket 输入携带服务器生成的管理权限；弹幕等外部输入只能创建待确认任务。客户端传入 `owner_control` 无效。

## 套餐与模型

Codex 使用 `ChatGPT` 登录，启动时移除 API Key 环境变量，强制 OpenAI/ChatGPT 登录并检查 `account/read`、`model/list`、`account/rateLimits/read`。只有明确存在 `gpt-6-astra` 才执行，无自动换模型或付费 API 回退，无自动购买或重置额度。

DeepSeek API 单独使用项目已有密钥和 `deepseek-flash` 配置，用于实时对话、语义意图识别及可选的 OMP 兼容调度。默认直接执行后台任务不再为固定的转交动作增加一次 DeepSeek 请求。Astra 使用标准服务档，单任务执行，默认超时 900 秒，队列上限 8。

只读检查：`.venv/Scripts/python.exe tools/check_agent_runtime.py`。
旧的隔离式真实调用脚本：`.venv/Scripts/python.exe tools/check_agent_pipeline.py`，它会创建执行器，使用前必须停止现有 8085 服务。它会实际调用套餐 Astra；`--image`、`--desktop` 分别请求绘图、读取桌面窗口信息。日常测试优先在任务台提交一个明确的小任务并查看真实回执。

## 持久化与任务状态

任务存储为 `data/agent-tasks/jobs.sqlite3`。第一次打开数据库时自动导入原有 `jobs.json`，保留任务编号、顺序、产物路径和已有可选字段，原文件保持不变。迁移标记与导入记录同事务提交；迁移失败不会留下半份数据。后续启动只读取数据库，不重复导入，也不再双写 JSON。原 JSON 是迁移前的保留副本，不是持续更新的运行记录。

`TaskService` 是独立于 HTTP 和执行器的状态命令入口，按已提交的状态验证合法转换，成功落盘后才更新共享任务字典。终态任务不能原地改回运行；继续或修改仍要创建关联修订。SQLite 按变更任务更新行，不因某个工具步骤或声音回执重写全部历史；多条关联记录可在同一事务提交，意外的旧写入端不能覆盖较新的行版本。

三类版本分开记录：

- `revision`：任务状态、需求、权限相关信息、执行方式、产物和修订关系等语义变化，用于确认凭证与对话回执的过期检查。
- `progress_revision`：执行器真实进度记录的变化。
- `delivery_revision`：声音通知派发、播放反馈与去重记录的变化。`delivery.revision` 仍指向这条声音对应的任务语义版本。

工具进度、预算计数和声音反馈不会反复推进任务语义版本，也不会仅因刷新进度就使修改确认失效。UI 查询和语音回执都从同一执行服务取得状态。

修订确认先持久化消费一次性凭证，再取消旧执行。取消完成后重新检查队列容量和观众待批准请求，新任务与父任务的 `superseded_by` 关系同事务提交，成功后才进入执行队列。数据库失败不会产生未关联却已开始执行的子任务；旧进程可能已经停止，界面会明确报告修订尚未创建，需要重新预览。进程取消、文件应用和音频播放不属于 SQLite 事务，不能随数据库失败回滚。

8085 执行服务自身重启时，未完成任务会标记为已取消，不自动重放执行或历史声音。数据库记录不代表操作能在崩溃后自动续跑；主程序的正常重启则不重启执行服务。

## 结果与权限

### 网页逐笔绘画

工作室默认选择“逐笔手绘”；原来的图像生成保留为“生成插画”。聊天绘画请求默认进入逐笔手绘。
Astra 生成 `drawing.json`，主机验证尺寸、颜色、点数、坐标、笔压和时长后才提供给画布。
从任务卡片打开画布，可开始/暂停、0.5～4倍速、从头重画、保存当前PNG。阶段名称和笔数跟随实际播放位置。
“直播纯画布”提供无控件页面，可作本机浏览器素材；页面参数 `clean=1`，跟随后台共享播放时间线。控制台的暂停、调速和重画同步到直播画布。
新任务先生成草稿，画布可预览并确认修改，或继续上色与细节；每个阶段独立生成完整笔画后播放。新版本准备好时共享画布切换并暂停。未实现逐笔生成或视觉反馈重规划；旧作品文件保留。详见 [2026-09-20更新](companion-optimization.md)。
后台“完成”表示笔画数据已准备，画布“画完了”才表示播放完毕；不是将一张生成图片逐渐揭开。

任务目录在 `data/agent-tasks/<任务ID>`，生成文件必须真实存在且位于目录内，不能用缺失文件或目录外路径充当产物。代码交付为“改动待审核”，本机确认后可以应用文件；不会自动重启运行中的项目。执行端验证说明与主机确认的文件存在性分开显示，不能把说明等同于独立语义验证。

Codex 命令/文件审批显示原始操作供本机批准；拒绝、取消、超时不会报告成功。尚不支持的交互请求明确拒绝，由执行代理报告阻塞。任务重新启动后不会自动重放，避免重复操作。

桌面/图像使用 Codex 实际发现的 Skills 和工具。Skill 本身不等于工具可用；缺少内置能力时不能偷偷调用付费 API。桌面输入和图像生成是否可用以真实调用结果为准。任务产物仅在本机界面提供，HTML/SVG/脚本作为附件下载，防止生成内容取得管理权限。

## 独立代码开发与应用

代码任务会在任务目录的 `workspace/` 创建源码快照，Astra 只改副本。首版纳入 brain、body、tests、tools、docs 及根目录文本源码，不复制密钥、config、运行数据、虚拟环境、模型或 Minecraft/第三方项目。依赖不足或超出范围时，应报告限制。

完成后由主机比较前后文件，保留完整差异、实际命令的退出码及输出，并编译检查变更的 Python 源码。识别 unittest/pytest、node tests/、npm test 命令；没有成功测试记录、有失败测试或 Python 语法错误时不能应用。测试记录不等同于产品行为已验证，审核时仍应检查测试是否覆盖需求。

本机任务台点击“查看代码改动与测试”，查看差异预览及 implementation.md 中的使用/预览步骤，再点“确认应用这些文件”。这里只展示源码预览，不自动运行未知网页或启动预览服务。

审核结果及待应用字节保存在执行目录之外的 `data/code-reviews/<id>`；应用使用这份固定版本。应用前核对全部原文件哈希，任何文件变化都会阻止整项应用，避免覆盖期间其他人的工作。保留 baseline 原文件；普通写入错误会回退已写入文件，进程/机器在写入中崩溃仍需根据 baseline 检查恢复。

应用后状态为“文件已应用 · 待重启验证”，不会自动重启主服务、修改运行中的技能注册表或承诺功能已经生效。新工具的注册代码可以随任务一起开发，通过审核并重启后再验证。旧版仅有草稿文件的任务没有源码快照，需要重新提交。

## 任务与对话协调

任务记录包含请求人身份、原始消息编号、来源和状态版本。B 站优先用平台 viewer_key 关联，昵称相同不会合并；没有平台身份的来源才退回来源与昵称。Web 请求不能自行设置 task_id、task_notice 或主播权限。

接单确认和异步结果都绑定同一任务，仲裁队列合并同任务的旧通知。任务通知不带 forced，不打断当前生成/合成/播放；可保留 5 分钟，过期后在任务台查看或主动查询。播报前重新取状态，不会把几分钟前的“正在排队”照读。

生成任务回应前主动同步状态；TTS 完成后、音频排队转播放前按最新同步快照核对状态版本。主界面每约 0.5 秒同步一次，独立任务台的取消可能有短暂传播延迟；收到取消/版本变化后会丢弃旧音频。重连重播和暂停恢复也重新检查。同版本按投递记录去重，播放失败只有有限补播机会；派发不代表客户端已经听完，也不保证端到端恰好播放一次。主程序新连接跳过连接前的历史语音通知，结果仍可在任务台查看。

可以说“做好了吗”“刚才那个进度怎么样”“取消刚才那个”，默认关联本人最近任务；也可说“查询任务 <完整编号>”“取消任务 <完整编号>”。观众不能查询或取消别人的任务，主播可以按完整编号管理。旧版本未记录归属的任务不猜关联关系。

角色聊天还会收到当前请求人最近三项任务的状态摘要，优先于聊天历史中的旧进度；待审核、已应用、版本验证通过分别看待。目前应用只更新文件，仍不自动宣称功能已生效。主程序通过内部协议同步状态，暂时断开时报告状态未确认，不能用旧缓存假装任务正在进行。独立 8085 任务台不播放直播声音；主程序在线时可接收新通知并反馈实际播放状态。

## 可靠性与统一工具入口

### 2026-09-11 验证与修订更新

测试命令的开始、结束事件由宿主记录完整源码清单及 SHA-256。只有两份清单与最终候选源码相同，测试才有效；测试之后编辑源码或文档，需要重新测试。应用前同时核对原项目的完整清单，依赖文件变化也会阻止应用。旧任务缺少版本凭证时不能直接应用，需要创建修订重新测试。哈希覆盖的是源码快照允许的文件，不包含外部服务、虚拟环境和运行数据；它不能代替测试内容本身的质量审核。

修订入口先返回影响预览，不立即取消任务。任务台显示保留的产物和修订方式，确认后携带一次性 token 执行。预览两分钟失效，状态、产物或要求变化需要重新预览。聊天收到预览后发送“确认修改任务”；按请求人隔离，观众修订仍需主播批准。工具 task.amend 同样先无 token 预览，再带 token 确认。

代码健康检查核对完整测试版本。通过后任务台提供独立的人工功能验收：填写操作步骤、预期结果、实际结果，明确记录通过或未通过。提交时再次核对服务启动编号与源码版本，记录绑定该版本；历史记录不代表新版本通过，也不自动代表所有功能通过。

本次本机回归覆盖两名同名、不同 viewer_key 的并发请求、进度、修订确认与取消，以及两个 WebSocket 客户端的音频归属、断开和重连。这是本机协议联调，不是两个真实 B 站账号或直播姬听音验收。

实际直播待验收步骤：两名观众各发起任务并查询自己的进度；其中一人预览、确认修订，另一人取消任务，检查没有串单；播放通知时断开并重新添加直播浏览器素材，检查有限补播且不读旧通知；最后在观众端实际听音。将操作与观察结果记录在对应功能验收中。当前改动不会自行开播或发送弹幕。

- 选择 OMP 兼容调度时，DeepSeek 调度前探测原接口；区分认证、额度、限流、网络和超时。代理失败时只向同一接口尝试直连，直连成功仅为本次 OMP 子进程设置该域名的 NO_PROXY；不切换模型/服务商，不输出凭据。默认直接执行不经过这次 OMP 探测与转交。
- 任务默认 900 秒、4 次可计数的调度/执行启动请求、80 项可观察工具操作，仍单任务执行。OMP 路径最多允许一次尚未调用执行器的重新调度；直接执行路径不因网络回执丢失而自动再执行。此计数不是 Astra 内部所有推理轮次或精确 token 额度；超过工具事件上限会中断执行，不承诺已开始的外部操作可撤销。
- 后台仍一次执行一项任务，普通远程任务可与前台聊天并行。桌面任务只等待项目鼠标键盘控制释放；标记 local_gpu 的本地显卡任务在直播语音启用时等待。等待任务保持可取消的排队状态，无资源冲突的后续任务可先执行，不再因前台持续说话超过 180 秒而失败。任务台显示排队位置和实际等待原因。
- 自动通知记录 pending / dispatched / playing / played / failed。played 依据唯一音频客户端的播放结束回执，不能证明观众设备有声音或本人听见。失败 5 秒后进入一次补播机会，取消、跳过、状态变更不会无限重播；手动清空播控取消通知。主服务停机不补播历史通知。
- 任务卡片可补充要求；聊天可用“修改刚才那个：…”或“补充刚才那个：…”。正在执行的旧任务先取消；完成的任务保留产物，新任务通过 parent_id 关联。观众修订仍需要主播批准。代码修订基于原变更和当前源码核对后继续，冲突时停止；其他类型只读参考原产物。
- 任务台“工具目录”提供结构化参数、就绪状态、权限和返回状态。已连接绘画/代码任务、任务查询修订、Minecraft、音乐申请/本地曲库和 B 站搜索。使用本机同源的 tasks-action/call_tool 入口；它不让普通弹幕越过主播权限。聊天收到目录就绪摘要，但本轮角色聊天并未因此自动获得自由调用所有工具的权限。
- 独立 8085 控制台会把需要直播主循环的游戏和音乐执行工具标为不可用。Suno 仍半自动，RVC 仍依赖现有配置；请求被接收不能当作音乐已生成或游戏操作成功。

代码应用后手动重启主服务，再点“检查主服务版本”。检查私有 runtime-health 的 scope、就绪状态、有效启动编号及完整测试版本。暂时无法连接、尚未启动、检查超时或版本不一致均保留文件和 applied 状态，并显示具体诊断与差异路径。可重试检查，或在确认故障原因后主动点击“回退到应用前”；检查本身不自动回退。成功仍只代表版本与健康检查通过，不替代功能验收。并发验证使用批次标识，旧请求不能覆盖后来回退或更新的状态。


### 2026-09-12 资源调度与互动关联

任务提交可选普通任务（standard）或本地显卡推理/训练（local_gpu），修订继承资源类型。桌面任务始终占用 desktop 类别，不能用普通任务标记解除桌面互斥。游戏鼠标键盘控制与桌面任务双向检查占用；MC Mineflayer 使用自己的协议连接，不占桌面输入，因此不因 MC 协议动作而停止远程任务。

本地显卡任务采用保守策略：实时语音启用时不启动。当前独立服务在主程序正常关闭、释放前台资源后，可以继续处理原来等待的任务，不必重新提交。普通任务的执行器明确被告知仅做远程模型调用及轻量文件操作/测试，不能临时启动本地显卡推理或操作桌面。此机制是本项目的调度与执行约束，不是操作系统级 GPU 配额或外部程序隔离，不能抢占已经运行的显卡任务。旧 foreground_wait_sec 配置仅保留兼容，不再控制资源等待时限。

导演保存本轮实际说出的互动问题。只有相关回答才计入成功互动；设备/播放反馈优先回应，保留原问题，且不谎称已修复。无关弹幕、追问、关联不明的短句不会覆盖问题或延长超时。关联判断采用本地规则（明确选项、常见话题答案、有效主题词），不新增模型请求；隐晦的语义回答可能保留等待。人数按来源与 viewer_key 区分，显示和播报仍使用昵称。


### 2026-09-13 自然任务表达、真实进度与角色行为

保留明确的 `/任务`、`任务:` 和直接命令入口。包含承接引用、能力问句或自然修改表达的消息使用 DeepSeek 结构化意图识别，动作限定为新任务、修改、进度、取消、继续和普通聊天。轻量筛选在接收时执行，网络识别在消息被仲裁选中后执行，不阻塞弹幕接收；识别最长 2.5 秒、输出 384 token，使用项目已有 DeepSeek 配置。普通实时知识/天气搜索仍走原对话搜索。模型只看当前文字及最多六项本人任务摘要，不获得任务权限。

执行前由宿主检查任务归属、状态版本和待确认操作批次。多目标不明确时列出本人匹配任务，可回复序号或编号；空的绘画候选不会扩大到代码任务。修改先预览，回复“确认”或“就这么改”后创建关联修订；“算了”会同时撤销预览凭证。已取消任务的“继续”同样先预览并创建新修订，不承诺恢复执行器中断现场。观众新任务/修订仍需主播批准；原始需求取自用户消息，不能被分类器改写。超时、返回异常或状态过期不会执行猜测的操作。等待识别的消息不与其他弹幕聚合，减少请求被吞并。

任务台进度来自执行器实际开始/结束事件，以及宿主实际校验：检索、修改文件、生成图像、运行命令/测试和核对产物。展示最后一次有效事件的时间、最多 24 条记录及真实退出码。工具步骤结束不等于任务完成；没有百分比和预计时间，也不传递原始命令、工具参数或日志到进度摘要。每个工具事件不会自动打断聊天，口头通知沿用接单与最终状态等关键节点；操作审批留在任务台，主动查询可读当前进度。

角色行为使用运行期间的短时状态，不改写正式角色卡或观众长期记忆。明确要求简短、换装指令或忙于绘画时保持简洁。认真求助时立即收起挖苦的表达指引，并将口播情绪与自动表情收敛；程序崩溃、压力测试等技术描述不当作个人困扰。情绪有短暂余韵和恢复过程，输出给语音与模型的情绪/动作保持一致，明确请求的动作保留。绘画任务实际运行或认真求助后的短暂恢复期内暂缓自动另起话题，观众消息和任务通知仍正常处理。表达分寸依赖提示遵循；硬过滤作用于情绪与动作元数据，不保证每句话的措辞都合适。

### 2026-09-13 独立执行服务与连接恢复

主程序只持有 TaskClient，不再创建第二个 AgentTasks。后台服务在 127.0.0.1:8085 单独持有执行器与数据库；内部 RPC 需要本机连接及服务令牌，浏览器管理入口继续校验本机同源，普通弹幕不能构造内部权限。任务台动作共用宿主入口，执行器不能自行改写任务状态。

前台通过连接持续声明 desktop、local_gpu 资源占用；正常下播关闭主程序会解除声明。若前台意外断开，服务保留其资源占用，避免把“暂时收不到心跳”当作键鼠或显卡已空闲。任务台可显示失联原因，确认原前台/控制已经停止后点击“释放失联资源”；仍在线的会话不能从该入口释放。重连和显式释放后，等待任务重新参与调度。此保留只属于执行服务的运行期协调状态，不是跨机器的资源锁。

客户端使用服务启动编号和快照序号，拒绝旧实例或旧批次的迟到状态；内部请求有重复检测。连接失败后不会自动重发修改、执行或播放反馈来猜测结果，应该查看任务台的真实记录。该机制不等于外部操作或音频的 exactly-once 保证，也不提供执行器断点恢复。

本次验证使用本机 SQLite、模拟执行器以及客户端/服务端协议测试，覆盖迁移、事务失败、合法状态转换、进度和声音版本隔离、修订原子提交与断连生命周期。实际 Astra 生成、游戏输入、直播声音和主程序带全部外设重启仍需各自现场验收；本次未自动调用外部 Astra 或开启直播进行验证。
