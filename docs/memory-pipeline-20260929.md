# 记忆与回复流程优化（2026-09-29）

## 2026-10-29：保留策略与召回连续性

沿用现有记忆库，按核心记忆、稳定事实、临时状态、近期计划、经历和待办承诺区分保留与召回策略，没有接入第二套记忆插件或额外的向量服务。

- 临时词只作用于事实所在的原文分句。例如“我最喜欢草莓蛋糕，最近正在学画画”不会把草莓蛋糕偏好改成七天后过期。规则提取和模型提取共用生命周期限制；近期计划和经历不会因为模型遗漏有效期就永久保存。
- 有限期的观众信息依据原始消息时间计算到期时间，延迟写入不会使旧计划重新变新；角色承诺从交付时计算。新增的最后确认时间与首次发生时间分开，只有新的原话证据才更新确认时间。浏览管理页或召回记录不会延长有效期。
- 同条消息里同一属性被明确更正时，按原文最后的分句决定本次事实，再按证据去重；不同属性分别保留。较早消息延迟入库时保留为历史，不回滚较新的当前事实。
- 明确追问“你还记得我喜欢什么吗”时，不因刚刚召回过而压低同一记忆；“你知道我今天该怎么穿搭吗”不再被笼统当作回忆请求。承诺需要相关主题、承诺询问或明确续接才进入上下文。
- 稳定事实不会只因时间久就被当作不可信；旧经历和临时信息在弱相关话题中逐渐降低优先级。主动询问相关历史仍可召回有效记录；已过期、已忘记或被纠正的内容不能靠显式询问绕过状态过滤。
- 管理页显示记忆类型、最后确认时间和召回次数；运行状态显示本轮选中依据、排序分与新鲜度。新鲜度是时间排序信号，不表示事实真假或置信度，也不表示角色实际说出了该内容。

旧记录在读取时补充诊断字段，不批量重写正文、归属或有效期。已有错误或无期限的旧记录仍可通过管理页修改、忘记；本次不会凭规则猜测它们的新事实。QQ 私聊身份绑定、已送达才写入、群聊隔离、遗忘屏障和每轮最多四条的配置保持生效。诊断仍只提供给本地主控，不广播到 OBS、公开体验页或其他聊天对象。

后端规则需重启主服务后加载，界面刷新后更新。离线回归使用临时文件和模型替身，不读取真实记忆或向 QQ/B站发送消息。

本次验证：全项目 1,590 项 Python 测试中 1,589 项通过、1 项因符号链接权限跳过；随后针对模型错分临时状态、同句更正的最后补修，重新运行记忆、QQ 私聊及控制台权限等 130 项测试，全部通过。两组受影响的前端测试及 JavaScript 语法检查通过。全量日志保存在 `data/validation/memory-improvement-20261029-tests.log`。本次未重启正式服务、未批量迁移真实记忆。

## 记忆准确性

长期记忆先检查当前身份与话题相关性，再按重要性、置信度和时间排序。同一观众的基础加分不再让完全无关的偏好自动入选；明确询问自己的历史、核心身份和未过期承诺分别处理。本轮没有相关记忆时，允许返回空上下文。

记忆和时间支线沿用统一身份：有平台编号时按来源与编号隔离；一对一文字和语音共享本地称呼身份，其他没有编号的来源彼此隔离。仅提到他人昵称不能读取对方个人记忆。旧记录依据已有来源读取，缺少来源的个人记录不自动绑定给当前账号。显示昵称不是身份认证，多人共用本地称呼仍视为同一个本地身份。

模型抽取必须能在输入中找到连续原文片段，并保留完整子句；未被规则验证的关系只作为“观众曾说”的引用保存，不把模型标签改写成事实。常见否定、疑问和条件表达有保守检查；这不等于验证现实真假或支持所有复杂语义。工作城市、居住城市等明确单值属性使用稳定属性键，更新值时保留被替代的历史；已识别不同类别的最爱可以并存。未知类别不强行互相覆盖。

不会批量删除、重写或自动纠正过去的记忆正文。旧记录继续受有效期、纠错状态、遗忘屏障和身份过滤约束；明确的新陈述才会更新对应事实。管理页修改或忘记后，诊断区不再显示旧摘要。

## 分段回复与写入

同一输入的抽取按原始事件证据合并正在进行的请求，并缓存最近 128 个输入的候选结果。并发任务有数量上限；抽取失败可以后续重试，一个等待者取消不会中断其他等待者。缓存仅在本次服务进程内使用。

输入事实只需抽取一次；角色后续真正播出的承诺仍逐段处理，避免第二段承诺被去重遗漏。原有证据去重、转写修改与撤销、语音记忆确认以及遗忘后的旧任务拦截继续生效。

## 回复规划和耗时

普通聊天直接回应。明确比较、操作步骤和多个条件的问题会加入少量固定回答约束，帮助先回应重点、按必要维度说明并提示缺失条件。该规划是本地规则，不增加模型请求、不打开模型思考模式，也不记录或展示隐藏推理。现有角色风格、安全路线和口播句数限制保留，复杂或含糊意图仍可能识别不完整。

长期记忆和认知记录并行读取；`selective_memory.context_timeout_sec` 默认 0.75 秒，各异步来源独立预算，超时保留其他成功返回的内容。审计准备使用相同等待预算，超时后继续回复。该预算限制异步等待，无法抢占正在执行的同步计算。总回复耗时从准备上下文前开始记录，另提供记忆检索、认知检索和审计准备的阶段耗时。

## 播放记录与控制台

认知审计区分生成中、等待播放、全部播完、失败和仅文字。完成合成不会自动记为已经说给用户；只有所有预期段落都有实际播放完成回执，才记录完整交付。跳过、过期、队列丢弃、中断和无音频失败都不能翻成成功；重复或乱序回执不会重复计数。浏览器回执不代表测量了扬声器实际出声。

主控的“高级设置 → 记忆管理 → 查看本轮记忆选择与回复策略”，或“运行状态”页的对应栏目，显示最近一轮的选中记忆、未采用原因计数、回答策略和播放审计。选中不代表最终回答一定用了这条记忆。诊断仅通过本地主控接口读取，不发送到朋友测试页、OBS WebSocket 或体验指标导出。
