# QQ 聊天

QQ 是现有主人格的聊天入口，支持配对后的本人私聊，以及群聊中 @ 她的文字消息；可用文字或语音回复。通道在固定版 DeepSeek Harness 0.2.1-rc.2 中运行，使用腾讯官方 QQ Bot SDK 1.0.5 和扫码连接器 1.2.0；回复由项目已经配置的主人格模型生成。腾讯原版 dsh-qqbot 的会话管理没有直接载入，因此不依赖其旧版会话恢复接口。

## 开始使用

1. 重启主服务，打开主页菜单中的 **QQ 聊天**，或访问 `http://127.0.0.1:8080/qq`（自定义端口时使用对应端口）。
2. 点击 **开始扫码绑定**，等本地通道就绪后打开页面提供的腾讯绑定链接，用手机 QQ 完成机器人绑定。绑定成功后自动连接，界面显示实际连接状态。
3. 要在群里聊天，将机器人加入 QQ 群，发送文字并 **@ 她**即可。群聊无需身份配对，未 @ 她的普通群消息不会进入对话。
4. 要私聊，在第二步填写你在主聊天页面使用的称呼。主页面默认称呼是“你”；使用过其他称呼时填写相同名字，才能读取属于该身份的已有记忆。
5. 点击生成配对码，在刚绑定的机器人 **QQ 私聊**中发送完整的 `QQ-…` 配对码。配对码十分钟有效，只能成功绑定一个账号。收到配对回复、网页显示身份已确认后，即可私聊；其他 QQ 身份的私聊不会进入主人格。配对码只在私聊中生效，不要发到群里。
6. 在 **回复方式** 中选 **文字** 或 **语音**，同时作用于私聊和群聊，从下一条消息生效。默认文字，选择会保留到下次启动；正在处理回复时需等本条完成再切换。

打开管理页面不会自动登录。重启服务后，点击 **重新连接** 使用已保存的机器人凭据；无需每次扫码。首次登录是否完成、机器人是否可用仍取决于腾讯绑定页面与 QQ 返回结果。

## 对话与记忆

- 私聊使用相同的人格配置、主人格模型连接和已绑定身份的既有关系记忆，保留话题开始、结束、切换及接话策略。
- 群聊沿用相同人格和模型，每个群中的每位成员分别保留对话与话题。不同群、不同成员和本人私聊互不混用，也不读取本人长期记忆；同一个人在群里说话不会被当成本人私聊继续处理。
- QQ 使用独立的短期历史、话题和回复状态，不进入直播消息队列、网页聊天广播或公共播放队列。
- 只在明确发送成功后记录她的回复。真实收到的用户消息会先保存；生成失败或发送结果不明不会被写成已经完成的回答。
- Gemini 回复关闭过程摘要，并请求仅含 `reply` 字段的结构化最终正文；本地严格检查 JSON 字段及正文，发送端再次拦截中英文过程标题、草稿标签和残留控制标记。格式异常时最多重新生成一次，仍异常则只发送固定失败提示；既有异常回复保留归档，但不再作为人格的后续上下文，也不会送入语音或文字兜底。
- 每段独立历史保留最近 32 条用户消息及对应的已确认回复，重启后可以续聊。已配对本人私聊在回复明确发送成功后，用单个有界后台任务抽取长期记忆，不阻塞下一次回复；未发送、失败或结果不明的回复不会触发写回。待处理标记随这 32 条历史持久保存，旧项会随历史淘汰；保留项可在后续发送或重新载入会话时重试，最多尝试 3 次，耗尽后不再自动重试，也不会重发 QQ 消息。
- 新的私聊长期记忆绑定机器人与本人 QQ 账号的摘要，只允许相同绑定的私聊召回；本机本人控制入口可按已绑定称呼管理和召回。不同 QQ 账号即使称呼相同也不能读取旧账号的私聊记忆，群聊和弹幕均不可读。私聊记录不进入公共概念图、认知审计或全局学习；修改、遗忘会保留作用域并使旧的后台写回失效。
- 网页与 QQ 使用同一套上下文预算。QQ 的正文格式指令和格式重试提示也在实际调用前复验；超过预算时不调用模型，不截断当前问题或结构化证据。历史和普通检索资料可以整块舍弃，纠错必须保留。
- 群聊最多保留 512 段磁盘会话，内存中最多缓存 32 段；按群和成员隔离保存。
- **开始一段新私聊**清除 QQ 私聊短期历史，保留既有长期记忆，不清空群聊。**解除 QQ 身份绑定**清除当前私聊上下文，并要求重新配对；不会解绑腾讯机器人本身，也不会阻止群聊 @ 回复。
- 主控记忆管理中的删除或更正会同步清理对应身份的 QQ 私聊上下文，不把更正内容带到群里。存储异常时暂停处理，避免继续使用旧内容。

支持已配对的本人私聊和群聊 @ 文字输入，输入最多 4000 个 Unicode 字符，回复最多 2000 字。群聊回复关联触发它的原消息，不接收普通未 @ 消息。没有开放语音输入识别、图片、文件、主动推送或从 QQ 执行 B 站/终端工具。

## 语音回复

私聊和群聊共用回复方式开关。语音模式沿用当前 TTS 后端、参考音色与语音设置，直接生成 QQ 语音条。日常回复会使用适合朗读的表达，仍先执行最终正文检查。无需额外音色配置，也不需要公网音频地址。

- 与主页面合成共用排队锁和显卡资源授权，但使用私有临时目录，不在主页面或直播中播放。
- QQ 的 IndexTTS2 完整回复使用单束合成，避免长句自动切换三束后超过等待预算；保留原参考音色和表达设置，不修改主页面的 TTS 配置。
- 语音服务在后台独立检查就绪状态，加载或暂不可用时先发完整文字；保留语音开关选择，就绪后下一条恢复尝试语音。状态可在 `/runtime` 查看。
- 本项目限制每条合成输入不超过 300 字、音频不超过 60 秒和 3,500,000 字节。超限、合成失败或合成超时会在发送前改为完整文字，不截断内容。Mock TTS 不支持语音。
- 配对确认和故障提示始终用文字发送。管理页会区分正文超长、合成超时、服务不可用、音频无效等固定原因；开关仍保留语音选择，下一条会再尝试。
- 临时文件在生成结束或取消后清理；待发音频仅通过本次运行的本机鉴权接口提供给 QQ 通道，收到回执、超时或断开后丢弃。
- 上传文件时禁止自动发送；上传成功且当前连接仍有效后，才发送一条关联原消息的语音。最终发送结果不明时不补发文字或语音，防止重复回复。语音的发送回执等待最长 90 秒。

## 状态与故障

QQ 完整回复默认允许模型处理 90 秒，由 `persona_llm.qq_timeout_sec` 控制（大于 0 且不超过 90 秒），包含一次格式重生成的总时间。它独立于主页面口播的 `timeout_sec`；Gemini 的单次请求也使用这份 QQ 预算，不再被口播默认的 45 秒提前截断。语音合成在正文完成后另行处理。模型超时、连接失败、授权、配额和正文格式失败会显示固定原因，不公开接口返回原文或聊天内容。

连接采用 QQ 官方 WebSocket。断线后 SDK 按平台机制恢复，管理页显示重连状态；不可恢复时可断开后重新连接。断开会取消排队和生成中的回复；已经提交给 QQ 的发送可能完成，无法撤回网络中已经发生的操作。

消息标识先持久化再调用模型，回复发出前再次写入发送记录。七天内收到相同消息不会重复处理，发送超时、回执丢失或重启后结果不明都不会自动重发。此时管理页会显示未确认状态，可以在 QQ 中查看实际结果后发送一条新消息。每个私聊对象或群最多排队 8 条，传输通道共计最多 32 条；主服务最多接收 8 个在途请求，超量时忽略输入。

QQ 数据位于 `data/qq/`：

- `credentials.json`：机器人凭据，仅本地服务与 QQ 通道使用，不返回管理页、不发送给模型。
- `channel.json`：已配对身份、回复方式、消息去重与发送状态，不存聊天正文。
- `conversation.json`：本人独立的私聊历史。
- `groups/<sha256(app,group,member)>.json`：按机器人、群和成员分别保存的群聊历史，文件名使用这些标识的摘要。
- `transport-status.json`：连接与消息处理的诊断计数、字段类型/长度和过滤原因，不含消息正文、账号 ID 或凭据。
- `harness/`、`workspace/`：QQ 通道的独立运行目录。
- `voice-temp/`：语音合成的私有临时目录，每次合成完成或取消后清理对应文件。

这些文件均在项目忽略的 `data/` 下。管理页面和控制接口只允许本机访问，修改操作要求同源请求；朋友测试模式不启用 QQ 服务。

## 依赖与验证

首次安装依赖可在项目根目录执行：

```powershell
npm.cmd ci --prefix tools/deepseek-harness --ignore-scripts --no-audit --no-fund
npm.cmd ci --prefix tools/qq-harness --ignore-scripts --no-audit --no-fund
```

本地检查覆盖身份配对、私聊与群成员的隔离对话、群聊 @ 过滤、话题与记忆删除、重复消息、发送回执、页面权限、SDK 消息格式，以及真实 dsh 插件的启动和关闭。检查使用模拟 QQ 收发和模拟模型，真实账号扫码与 QQ 消息往返仍需绑定后验证。

腾讯参考实现：[dsh-qqbot](https://github.com/tencent-connect/dsh-qqbot)。通道开发协议见 [QQ Harness 说明](../tools/qq-harness/README.md)。
