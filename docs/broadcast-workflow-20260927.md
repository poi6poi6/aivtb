# 直播准备、节目衔接与待答问题（2026-09-27）

本轮在源码中加入五项直播功能：开播演练、等待与故障提示、节目单串词、OBS 栏目进度牌、待答问题卡。

**本轮没有重启正在运行的服务，也没有调用真实模型或语音 API。下列能力尚未在实际直播现场激活或验收。** 下次重启主服务后，刷新页面，从运行状态页开始演练。点击演练或准备提示音时，才会使用你已配置的实际模型和语音服务；不要把本轮自动化测试结果当作现场音频检查。

## 页面入口

以下地址使用默认本机端口；如已修改 `webui.port`，请使用实际端口。

| 用途 | 地址 |
| --- | --- |
| 主控对话、固定待答问题 | `http://127.0.0.1:8080/` |
| 运行状态、应急提示音准备 | `http://127.0.0.1:8080/runtime` |
| 开播链路演练 | `http://127.0.0.1:8080/rehearsal` |
| 栏目卡片与节目单 | `http://127.0.0.1:8080/shows` |
| 投票管理 | `http://127.0.0.1:8080/polls` |
| OBS 栏目进度牌 | `http://127.0.0.1:8080/show-stage?clean=1` |
| 待答问题卡 | `http://127.0.0.1:8080/questions` |

新增管理页面及接口只接受本机访问，朋友测试模式不可访问。OBS 栏目进度牌也需要通过本机地址使用。

## 1. 开播前走一遍声音链路

先打开主控或 OBS 主播放页，允许浏览器播放声音。在 `/runtime` 点击“开播前，进行一次演练”，进入 `/rehearsal` 后开始一轮。

演练会读取当前弹幕连接状态，让当前模型生成一句短句，使用当前 TTS 音色合成，并等待主播放页的开始与完成回执。本页不会另开播放器；演练内容不计入观众互动和记忆。正式回复正在生成、合成、排队或播放时，以及暂停播放或语音资源被占用时，不能启动演练。

- 弹幕已启用时，需要连接在线且最近心跳在 90 秒内；未启用时明确跳过，不算已验证真实弹幕。
- 模型备用回复或 mock TTS 不能代替真实模型、真实语音阶段通过。
- 默认等待主播放页回执最多 30 秒；断线、播放错误、取消或超时都会使本轮不通过。
- 自动检查完成后，仍需在实际设备上试说一句，检查麦克风收音、识别及听感，并在页面确认。
- 在实际 OBS 场景里检查电平和音轨，再通过监听或短录制确认声音已进入 OBS、没有重音或漏音，然后确认 OBS 检查。

**浏览器回报“播放完成”不代表系统检测到了扬声器出声、麦克风正常或 OBS 收到了正确音轨。** 两项人工确认都完成，页面才显示本轮通过。更换设备、场景、音轨或音色后，应重新演练。

## 2. 等待与故障提示

主控和播放页会显示简短等待提示。默认阈值如下，可在 `config/settings.yaml` 的 `broadcast` 段调整；已有配置优先于默认值。

| 设置 | 默认值 | 行为 |
| --- | --- | --- |
| `wait_notice_sec` | 8 秒 | 回复或合成等待较久时显示提示 |
| `reply_timeout_sec` | 45 秒 | 单轮回复生成的等待上限 |
| `synthesis_timeout_sec` | 60 秒 | 单段语音合成的等待上限；也用于提示音准备 |
| `failure_limit` | 3 次 | 模型或语音阶段连续失败达到阈值后，暂缓自动接话 |
| `cooldown_sec` | 30 秒 | 暂缓期限；到期允许新的回复尝试 |

同一轮、同一阶段的重复错误只记一次；阶段成功会清除该阶段的连续失败计数。冷却期间仍可手动提问，不会自动重放刚才失败的回答。故障口播/画面提示有 30 秒间隔，避免反复打断直播。运行状态页显示当前暂缓状态。

在 `/runtime` 点击“准备当前音色提示音”，才会提前合成固定应急短句。生成成功后，故障时可使用已有音频，不需要再请求故障中的语音后端；没有可用提示音时保留画面提示。暂停播放时不会插播该音频。

提示音与当前 TTS 配置、参考音频文件及内容校验绑定。配置或参考音频变化、音频损坏时不沿用旧音色，需要重新准备；不会为了应急自动切换到其他音色或后端。

## 3. 按节目单衔接栏目

在 `/shows` 创建本场和卡片，选择“本轮栏目”，点击“开始这张卡片”。环节顺序为：

`介绍委托 → 观众投票 → 准备草稿 → 看画讨论 → 命名收束 → 本轮结束`

点击“下一环节”推进，不需要的环节可以略过；“结束本轮栏目”只结束当前卡片的节目环节。投票创建、平票或零票选择、提交绘画、修改草稿和确认上色仍由主播操作，推进环节不会执行这些任务。

点击“开启直播节奏”后，导演才会围绕当前栏目和已确认进展安排少量串词。同一环节的同一种状态避免重复主动提示，状态不明时不编造完成结果。手动模式、绘画专注及故障暂缓仍会限制主动发言；备用暖场话题有 10 分钟冷却。

节目单不会按聊天轮数自动换环节、替主播发起下一场或自动批准任务。重启主服务后会保留卡片与当前环节，但必须再次点击“开启直播节奏”，才能恢复节目串词和进度牌展示。关闭直播节奏不取消已有后台绘画任务。

卡片、投票委托、历史作品及跨场续作的完整操作见 [栏目手记说明](show-sessions.md)。

## 4. 在 OBS 显示当前栏目

添加浏览器源，使用 `/show-stage?clean=1`，建议宽 760、高 420。这个页面只展示本场主题、栏目标题、当前环节、已确认进展、下一环节及本场待处理绘画委托数；它不播放声音，也没有写操作。

栏目主题、卡片标题和命名属于公开展示内容，私密说明应留在卡片笔记中。进度牌不会输出绘画原始要求、私密笔记、下次待办、观众账号标识、任务编号、工具步骤或异常详情。断线或进度无法确认时会标注状态过期，不补造执行百分比或完成时间。

## 5. 把问题留成待答卡

在主控聊天或弹幕旁点击“固定待答”，或进入 `/questions` 手填。固定按钮引用服务器最近收到的原事件，浏览器不能替换来源和账号。未选中的弹幕仅进入有限的临时引用缓存，不写入问题卡数据库；缓存超过 30 分钟或被后续消息挤出时，可手动填写问题。

同一原事件重复固定不会创建第二张卡。卡片保存原事件归属，显示时只使用昵称和来源；账号标识不进入 OBS。数据在 `data/question-cards.sqlite3` 中，问题最多 1000 字，待处理卡片最多 100 张，全部保存卡片最多 500 张。达到总量上限后，可主动删除已撤回的卡片。

- **待答 / 暂放：** 点击“现在回答”，通过现有主控对话和语音流程执行。
- **正在答：** 表示已进入调度或回答流程，不代表观众已经听到答案。
- **已答：** 必须同时确认回复生成结束、预期的每段语音完整播完，才由主控回执更新。生成结束、提交成功或只播完第一段都不能标为已答。
- **停止或撤回：** 先请求主控停止该轮，确认后回待答、暂放或撤回；停止未确认时保留当前状态，避免重复调度。
- **失败与恢复：** 生成、合成、播放失败，打断、清空或过期会保留未完成事实。服务重启后，遗留“正在答”恢复为待答，不自动重放。旧回执不能把后来撤回或重新调度的卡片改成已答。

如果调度已关联回答编号但回执异常，页面会明确提示未确认，请先停止本次回答后再试。多页面使用版本检查，遇到状态变化应刷新核对。待答卡的“已答”仍依据浏览器播放回执，不能代替现场扬声器与 OBS 听音检查。
