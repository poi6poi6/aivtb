# 受控自举：让系统开发和升级自己

后台任务台 `/tasks` 新增“系统自我改进”。它复用已有 Codex / Astra 执行服务：记录问题，在独立源码副本中开发，由宿主执行独立验收，再按运行方式等待人工应用或在空闲时升级。主程序之外的升级进程负责服务切换和失败恢复。

## 使用现有 ChatGPT 套餐

执行沿用项目现有的 Codex ChatGPT 登录与 `gpt-6-astra`。点击任务台顶部的“检查套餐连接”确认本机账号能使用该模型；不需要额外填写 OpenAI API Key。系统读取执行服务报告的额度，在低于配置的保留比例时停止提交新开发任务。它不会自动购买额度、消耗重置次数、切换付费 API 或改用其他模型。

套餐额度属于整个账号，并非本项目专用余额；其他 Codex 会话也会消耗额度。这里的比例是执行前准入条件，不是账单上限，也不能保证一个已经开始的请求恰好停在该比例。登录、模型权限、额度数据不足或执行环境无法连接时，应查看实际阻塞记录，不能把“已接入 Astra”理解为任何时候都可执行。

日常陪伴的 DeepSeek / IndexTTS 流程仍按原配置运行；此设置只控制系统改进任务。

## 三种运行方式

| 方式 | 行为 |
| --- | --- |
| 仅记录改进方案 | 默认方式。收集问题和手动目标，不自动调用 Astra 开发。 |
| 自动开发，等待应用 | 在允许范围内创建开发任务并独立验收。查看完整改动后决定是否升级。 |
| 在指定范围内自动升级 | 开发和独立验收完成后，等待主服务空闲及升级条件满足，再切换版本并检查。 |

默认允许路径为空，不会自动开启开发。展开“运行方式与允许修改的范围”，每行填写一个相对于项目根目录的文件或目录，例如 `brain/static/face.js` 或 `docs/`；目录以 `/` 结尾。应选择具体功能范围，不要填写磁盘绝对路径、上级目录或通配符。最终是否准许修改由宿主检查，输入路径不能放开被保护的文件。

还可设置每个问题最多尝试 1–3 次、最近 24 小时最多创建 1–10 项开发任务，以及至少保留 5%–50% 套餐额度。初始值分别为 2 次、3 项和 20%。点击“保存运行设置”后才影响执行；页面刷新不会保存尚未提交的草稿，也不会自动创建任务。

## 日常操作

1. 用“添加一个改进目标”描述问题、期望行为和可检验的结果。提交只表示已记录，是否开发取决于当前模式、范围、预算和执行条件。
2. “检查可改进问题”读取主服务上报的后台工作模块状态，连续三次检查失败才形成改进目标。相同问题合并记录，受尝试次数和任务数量限制；它不是对整个项目无限循环的自动审计，也不把服务没启动直接当作源码故障。
3. 在问题卡片点击“查看开发任务与完整改动”，检查现有任务卡中的逐行差异、测试命令、输出和执行进度。状态区分别显示开发、独立验收、等待空闲、版本切换与恢复。
4. 待验收的改动可点击“运行独立验收”；满足条件后可点击“升级到此版本”。接受请求只代表开始处理，须继续查看“最近升级”的实际结果。
5. “停止自举”撤销后续自动执行。若已进入服务切换，升级进程会按实际阶段完成必要恢复，不以中断恢复流程来表示停止。普通任务的“停止全部任务”与自举停止属于不同操作。

后台开发完成不代表主程序已使用新文件。“独立验收已通过”“新版本服务检查通过”和实际功能验收是不同阶段。B站搜索能否取得播放量、TTS 是否出声、浏览器能否自动播放、OBS 是否收到声音，需要使用实际环境验证。

## 独立验收与升级恢复

开发代理只能提交源码候选。宿主固定验收命令并检查候选版本，不能把开发代理自行写的“测试通过”当作发布依据。基础冒烟测试之外，已映射的业务文件还会运行固定的相关测试；未建立验收映射的业务文件拒绝自动验收，需先由人工扩充宿主测试映射，不能仅靠通用测试放行。源码与验收记录发生变化、允许范围变化或验证条件不足时，必须重新核对，不能沿用旧结果。

独立升级进程在应用前再次检查允许范围、候选版本和当前文件；服务切换按“停止旧版本 → 应用已验收改动 → 启动新版本 → 健康与版本检查”执行。失败时尝试恢复旧文件并重启旧服务。恢复遇到后续文件修改、无法启动等问题，会显示“旧版本恢复受阻”或实际失败原因，不宣称已回滚成功。

自动升级要求服务提供可信的空闲状态；无法确认时继续等待或阻塞。手动请求也必须经过宿主的版本与执行条件检查。浏览器关闭不会取消后台执行，主服务切换时任务台可能暂时断开；独立任务服务的入口为 `http://127.0.0.1:8085/tasks`。

## 首版边界

- 审核、权限、预算、升级和关键验收控制保持独立保护，开发任务不能通过修改这些代码放行自己。
- 不自动安装依赖、下载或替换模型，不直接修改凭据或运行数据文件。不提供自动迁移流程；涉及记忆、身份、任务数据库等数据迁移的改动必须人工处理。路径范围检查不保证业务代码运行时没有数据副作用，审核仍须检查相关行为。
- 独立测试执行实际项目代码，不是操作系统级沙箱；不应给不可信来源无限范围、无限预算或无限工具权限。
- 自动发现依据系统已经上报的故障与手动目标，不能自动看见所有外设、浏览器或听音问题，也不会凭未观察到的效果宣称修复完成。
- 版本检查通过只证明相应启动和健康条件已满足，不能证明所有产品行为正确。Windows 服务切换、真实 Astra 开发和现场功能仍需分别验收。

本轮代码验证通过 154 项 Python 测试与新旧任务面板的前端测试；独立候选验收另在临时源码副本中运行了固定冒烟套件。2026-10-11 使用现有 ChatGPT 登录对 Astra 做了极短实际调用，经历连接断流重试后收到完整回复。实际套餐通道已确认可用，生产服务切换与回滚仍只做了模拟生命周期验证。

主服务必须从新版启动中心启动，才能上报可验证的主进程、启动器和清理进程身份；直接手动启动的 Python 主服务不满足自动切换条件。更新代码后需重新启动后台任务服务与主服务并刷新任务台，旧服务不会因网页更新自行获得自举能力。

如果升级记录停在“旧版本恢复受阻”，先检查控制器记录和正在运行的实例；在项目目录执行 `.\\.venv\\Scripts\\python.exe tools/run_upgrade_release.py --recover` 可按原有升级记录继续核验或恢复。控制器不会强制结束身份不明的进程；无法确认时仍会保留阻塞记录，而不是反复启动。

现有开发、审核、任务取消与套餐登录机制见 [后台任务说明](agent-tasks.md)。
