# 栏目手记与投票绘画委托

本机主界面进入 **栏目手记**（`/shows`）。数据保存在 `data/show-sessions.sqlite3`；朋友测试模式不能读取或操作这些页面和接口。

## 一场直播怎么使用

1. 填写本场主题并创建场次。也可以从往期手记点“接续待办，开启下一场”，把上场有待办的卡片、作品关联和投票来源带过来。
2. 在投票页结束一轮投票，点“按结果生成绘画委托”。唯一最高票会预填；平票、零票必须由主播选择。测试轮次始终标为测试。取消的投票不能生成委托。
3. 编辑栏目主题和绘画要求，保存卡片。茶会等不需要绘画的栏目可以留空绘画要求。
4. 点“保存并开始画草稿”。这会提交已有后台绘画任务；仍按原任务系统的资源协调与审批执行。打开画布修改草稿、确认上色，后续版本沿用同一个作品关联。
5. 记录作品命名、本场笔记和下次待办，点击“更新作品状态”。不会自动修改绘画或调用模型总结。
6. 收播时生成事实回顾。内容来自记录、实际投票和查询到的任务状态，区分草稿、上色版本、排队、失败及状态未确认。回顾不代表画面已在直播间播放。

## 断线、重复点击与版本

- 每张卡片的首次绘画提交都有持久化编号。若提交后回执丢失，刷新后点“核对提交”，不会因重试生成第二项任务；服务重启后同样去重。重复点击不会恢复或重放已取消的旧任务。
- 待确认提交会冻结该委托的绘画要求，避免用同一个编号执行两个不同请求；命名、笔记和待办仍可编辑。
- 默认收播会阻止尚未确认的委托。若服务长期不可用，可显式选择“带未确认委托收播”，保留提交编号及未确认事实。这不代表后台任务未创建或已取消，需到任务台核对。若该卡片有下次待办，可以在下一场继续核对相同委托。
- 多页面修改采用版本检查；旧页面不能覆盖新数据。遇到版本冲突，可先保留自己的修改内容，再点卡片的“重新读取此卡片”。普通定时刷新不会清空未保存表单。

## 历史作品与连续栏目

收播记录保存当时确认的绘画任务、版本指纹和阶段。“收播版本”打开独立只读画面，不跟随之后的画布修订，也不改变直播画布的播放状态。若原产物丢失或被改写，会明确显示不可用，不拿新版本冒充旧版本。当前实现引用原任务产物，不另复制一份，因此需要保留任务目录。

“继续修改”打开持续演进的作品画布。接续场次会将原待办放入本场记录，新待办留空，避免未经记录就无限复制。沿用的投票会明确标注来源场次及“不是本场参与”，不会冒充本场的新投票。

界面展示最近 30 场手记；数据库保留完整场次。页面不会自行开播、收播、播报回顾或执行下一场待办。

## 可选的直播节目单

在本场手记里选择卡片，点“开始这张卡片”。节目单按“介绍 → 投票 → 草稿 → 讨论 → 命名 → 本轮结束”推进，只有主播点击“下一环节”或“结束本轮栏目”才改变环节。不需要的环节可以略过。结束本轮栏目不会收播、取消后台任务或改写作品。

“关联当前投票”只关联已存在的轮次；创建投票、确认平票/零票选择、提交草稿和批准上色仍使用原来的明确操作。节目单会区分投票未关联、进行中、已取消、平票、零票、排队、等待审批及状态未确认，不把环节标题当成完成事实。

点击“开启直播节奏”才会允许导演为当前环节安排少量串词，不修改 `director.enabled: false` 的默认配置。串词仍遵循主控的手动模式、绘画专注和故障限制；不会靠聊天轮数自动切换环节。同一环节的同一种进展只安排一次主动提示。备用暖场话题使用 10 分钟冷却，耗尽时可以安静陪伴。重启主服务后会保留卡片和环节，但必须再次点击开启，才恢复自动串词与进度牌展示。

## OBS 栏目进度牌

使用 `http://127.0.0.1:8080/show-stage?clean=1` 作为 OBS 浏览器源，建议宽 760、高 420。它展示本场主题、当前卡片标题、环节、确认过的进展、下一环节和本场待处理绘画委托数。主题、卡片标题、命名会作为直播内容显示，私密备注应填写在“本场记录”里。

进度牌不播放声音，也没有写操作；仍只供本机访问，朋友测试模式不可访问。它不会输出绘画原始要求、卡片笔记、下次待办、账号标识、任务编号、工具步骤、原始异常或内部文件路径。任务状态取自主服务已有的新鲜缓存，不为了显示牌调用模型或重复提交任务。连接中断或进度无法确认时会显示“状态过期”，不推测完成时间和执行百分比。
