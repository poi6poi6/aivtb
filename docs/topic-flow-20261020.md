# 2026-10-20 对话话题生命周期

本次在现有的人格互动策略上增加统一的话题状态，让助手区分什么时候在延续、什么时候换题、什么时候应该停下。原角色卡和长期关系数据保持原样。

## 对话行为

| 你说的话 | 处理方向 |
|---|---|
| “今天开会，我说到一半又被打断了。” | 开始一个话题，保留最初讨论的事情 |
| “主要是我准备了很久。” | 延续原题，将本轮重点移到新补充的内容 |
| “嗯”“好”“谢谢” | 普通应答，不单独认定话题结束 |
| “顺便问一下，玫瑰怎么养？” | 临时插问，原话题暂放，不把原来的倾诉模式套到养花问题上 |
| “回到刚才的话题。” | 恢复仍可继续的主话题及其回应方式 |
| “换个话题，玫瑰怎么养？” | 明确切换，回应新内容，放下旧题的情绪和修正提示 |
| “这件事先不聊了。”“这个话题到此为止。” | 简短收尾，不再追问、给建议或自动开启另一个话题；停止讨论不等于问题已经解决 |
| 已结束后只说“继续” | 不自动复活已经结束的内容；缺少明确指代时简短确认想聊什么 |

没有明确标记的换题采用保守判断。明显的新领域问题可以换到新的焦点；仅仅缺少重复词，不能证明用户换题。含混短句不会凭空生成话题、情绪或结束结论。

## 实现

`brain/topic_flow.py` 是话题状态的共同来源。人格和对话记录共享同一个实例，按稳定用户身份隔离。它保留话题起点、当前重点、已经完整说出的相关内容及尚待回应的问题；数据以普通上下文提供给模型，系统提示只使用固定的行为规则。

话题起点不会因短期记录滚动而重置。状态与交付记录都有数量上限；近期语音更正可以撤回重放，超过可重放窗口的更正会保守清理该用户的当前状态。重复撤回不会再次清空状态。

`brain/dialogue_policy.py` 让倾听、建议、关切和修正状态跟随话题。临时插问不会覆盖主话题的交流方式，恢复主话题时可以接续；明确开始新话题后，不沿用旧题的负面情绪或纠正提示。`brain/reply_planning.py` 为明确结束提供独立的简短收尾策略，收尾回复限制为一句；模型调用失败时的备用回复同样遵守收尾。

`brain/conversation.py` 同步维护共同安排与中断位置。迟到的旧生成、部分播放及完整播放回执不能把已经放下的旧题重新设为当前话题，也不能恢复已结束的待办。公开弹幕历史仍按原逻辑保留，但当前焦点及新增话题提示按用户隔离。

`brain/director.py` 同步本地文字／语音聊天的话题边界。主人明确收尾后，普通自动闲聊暂停；旧的主动续聊和已进入语音队列的过期内容也会失效。正式节目单与直播投票继续遵循原有主持控制。

语音更正、撤回、记忆编辑和遗忘同步清理相关状态。提示预览不推进状态，重复事件不重复开题。所有识别在本地完成，不增加模型请求。
