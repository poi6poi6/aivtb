# 本地 B 站浏览助手

当前版本：**1.3.0 点播字幕版**。在扩展管理页重新加载助手，再刷新本机控制台；原点歌连接握手会显示 1.3.0，并声明所选分P字幕读取能力。新增点播评价需要主服务包含对应接口，升级项目后重启主服务。只看到“已连接”不能证明扩展已升级。1.3.0 沿用 1.2.0 已有权限；下面的 1.0.x 说明是保留的点歌功能更新记录。

点播字幕通过原点歌桥的独立 `read_video` 请求读取，不导航、不暂停播放中的视频，也不与搜索共用取消状态。只访问固定的只读视频元数据、WBI 签名参数、所选分P播放器及字幕CDN；不读取热评。CID 必须来自 `pages` 中明确匹配当前分P的条目，不能用视频顶层通常属于P1的 CID 替代。字幕最多 12,000 字、2,000 条，截断与无字幕、需登录、受限、分P无法确认分别返回。字幕不等于看完画面；何时让主人格评价由控制台明确请求决定。

在 Chrome 或 Edge 的扩展管理页启用“开发者模式”，选择“加载已解压的扩展”，选中本目录。回到本地控制台刷新页面，再点控制台的连接浏览器按钮。仅支持 `http://localhost` 和 `http://127.0.0.1`；换端口或刷新页面后重新连接。

扩展打开并复用自己创建的普通 B 站标签页。它读取页面上公开显示的视频标题、UP 主、时长、封面地址和明确标注的播放量，最多返回 30 个结果。`12.3万` 等文字保持原样，不冒充精确播放次数；读不到播放量时返回空字符串。查询页始终静音，并暂停其中的音视频，正式播放由控制台在角色介绍完成后负责。

如果页面要求登录、验证或拒绝访问，查询立即停止并说明原因。可以自行查看该标签页处理后重新查询。扩展不会读取或导出 Cookie、导出登录状态、点击验证，也不会自动重试或切换身份。点歌搜索仍读取正常网页结果；自主活动的 `read` 另使用固定只读 API 获取字幕和热评，详见下文。用户原有的其他标签页不受影响；如果手动把查询标签页导航到其他网页，下一次会新建查询页。

安装权限只有 `storage` 及固定网站范围：本机 localhost / 127.0.0.1、B 站搜索、视频、动态首页、个人空间、opus 动态详情、`api.bilibili.com`，以及字幕文件域名 `aisubtitle.hdslb.com`、`subtitle.hdslb.com`、`i0.hdslb.com`、`i1.hdslb.com`、`i2.hdslb.com`。字幕请求还受固定路径约束，不把域名权限作为任意页面访问入口。没有 `cookies` 权限。原点歌通道仍只接受搜索页和 BV 视频页，不因新增权限而接受动态或首页。会话存储保存已连接的本地页面身份和点歌标签页标记；活动发布与互动另保存不含正文的去重记录，详见下文。没有远程脚本、账号凭据或后端令牌。可在扩展管理页随时停用或移除。

页面结构可能变化，未知的统计位置会保守返回空值，不能保证每个版本的 B 站页面都能识别。当前提供模拟 Chrome API 和 DOM 的自动化测试；未通过真实账号页面验收。

遇到搜索有结果、播放量却未读到时，先点 **“查看 B站原始搜索页”**：它在新标签页打开官方关键词搜索结果，和控制台播放视频的官方播放器不同。旧版 1.0.3 也能打开原始搜索页；新 **“播放量读取诊断”** 需要助手 1.0.4。确认已连接版本后，查看原页与诊断即可继续定位，不必反复升级、重启主服务或 TTS。

1.0.4 在缺失统计时提供可展开的诊断，最多采样 2 张结果卡的有限统计组件结构和数字。字段包括可见性、经过白名单筛选的组件标记、数字解析结果和有限图形摘要；不包含搜索词、标题、作者、链接、cookie、页面全文或原始 SVG 路径，也不写入持久存储。未知播放量继续保持未知，自动选播门槛不变，手选仍可继续。本版用于收集排查依据，不代表现场识别故障已经修复或真实浏览器验证已通过。

1.0.1 增加连接版本和失败阶段诊断。诊断只返回固定的阶段/原因代码，例如创建标签页、静音、导航或页面校验失败，不返回浏览器原始异常、页面正文、查询参数或凭据。这能定位“没有打开页面/只出现空白页”的具体失败阶段，尚不代表已确认或修复浏览器中的原始故障。

1.0.2 修复浏览器计时器的调用接收者，并使旧请求清理失败不再吞掉结果或阻挡新查询。若 `crypto.randomUUID` 不可用，改用 `crypto.getRandomValues` 生成安全 UUID；两者均不可用时明确报错，不使用弱随机数。新诊断区分随机 ID、计时器初始化与通用请求处理，不再把所有内部异常都标成“准备查询”。这些行为仍需在真实浏览器验收。

1.0.3 扩展统计字段的公开语义识别，支持图标/ARIA/数据标记、嵌套数值提示、全角数字和繁体标签。标题先出现而统计稍后加载时，从首次结果起提供四秒统计宽限；每次成功提交仍要求整行（含统计）稳定至少一秒，采集总上限为24秒，外层请求上限为25秒。未知数值仍返回空值，不改变自动播放门槛。

部分卡片的播放图标只有内联 SVG 路径。兼容代码只识别完整的已知播放三角形路径，并要求固定统计组件、24×24 图标坐标和独立可见数值；不凭位置猜测，也不把播放/弹幕共用的矩形外框当作播放标记。该图形参考作者发布的 [MIT 源码中的公开卡片样例](https://greasyfork.org/zh-CN/scripts/501860-bilibili/code)，并非用户当前页面的现场证据；没有引入或执行该脚本的其他逻辑。图形或结构改变时会保守返回未知。

开发验证：`node tests/test_bilibili_browser_extension.js`（在项目根目录执行）。

## 独立的浏览活动通道

打开本机 `/bilibili-activity` 页面使用新功能。活动协议与原点歌协议隔离，只接受同一页面、同一来源的 UUID 请求，以及 `account`、`search`、`read`、`publish`、`verify`、`interact`、`verify_interaction` 七种固定动作。宿主停止任务时，仅当前待处理请求可转发取消；普通网络错误不会被当作取消或自动重发。

`account` 从登录后的账号组件识别 UID 和昵称，不把视频 UP 主当作当前账号。`search` 只返回可见搜索卡片的标题、作者和官方 BV 链接。`read` 先读取页面标题、简介和可见字幕，再通过固定 API 补充视频资料、字幕和热评。活动页中的媒体保持静音和暂停；没有视频画面理解或音频转录。

只读 API 限定为 `api.bilibili.com` 的 `/x/web-interface/view`、`/x/web-interface/nav`、`/x/player/wbi/v2` 和 `/x/v2/reply`，使用浏览器现有登录会话，不读取 Cookie 值，不把登录凭据交给宿主或模型。字幕文件只接受固定 HTTPS 域名及 `/bfs/subtitle/`、`/bfs/ai_subtitle/` 路径，且请求不携带凭据。接口跳转、响应大小、超时、风控和取消均有边界；失败时保留可用页面证据，不自动循环重试。

当前字幕只覆盖第一 P，选择一个可用轨道，优先中文；最多 12,000 字、2,000 条字幕。`full_subtitles` 表示取得了这个轨道的完整文本，`subtitle_excerpt` 表示超限截断，不能推断看完视频或其他分 P。没有取得字幕文件时，页面已显示的字幕标为 `visible_subtitles`，只有简介时标为 `page_metadata`。结果保留字幕语言、第一 P／总分 P 数、可用状态和截断标记。最多读取 10 条热评，每条最多 300 字；热评属于其他用户的观点。

活动页显示见闻证据、公开阅读日记、动态草稿、互动建议及其回执。公开日记保存于宿主本机，供网页／QQ 对话按话题召回，不会因保存而发到 B 站。Harness 只向宿主开放搜索、读取、见闻、草稿、日记和互动建议六工具；扩展不运行独立人格或调度器。

文字动态只在当前 UID 与 `expected_uid` 相同时执行。提交前先检查本人已加载的动态列表；存在相同正文时停止。随后要求编辑器为空、没有已识别的附加内容，写入正文并再次检查账号及编辑器。扩展在点击前持久记录草稿指纹和请求 ID，然后最多点击一次发布。正文里的视频 URL 保留在文字中，不额外创建链接卡片。

只有唯一匹配的本人动态候选、相符的可见发布时间、实际打开的动态链接、详情正文、独立验证的作者 UID 都满足条件，发布才返回 `published`。时间或作者节点只有 DIV 时，允许在自有标签页内点击该只读节点，读取真实跳转地址；未知结构、弹窗被拦截、账号变化或无法确认时保守返回 `unknown`。`verify` 可以不带动态 URL，从本人动态列表寻找唯一正文候选；但这要求扩展仍保留本草稿的提交时间。扩展重装或记录丢失、宿主也没有已知动态 URL 时，只返回未知，不能用任意旧同文动态推断本次发布成功。核验绝不会重新发布。

每次动作总时限为 50 秒。提交后的断线、关闭页面和超时都保留“结果未知”，不能据此再次点击发布。发布与互动共用的持久去重记录最多 512 条，保存草稿／互动 UUID、请求 UUID、内容与 UID 的 SHA-256 指纹、提交时间及已核验的动态地址，不保存正文；记录满后停止新提交，不自动淘汰记录来重新放行旧请求。浏览器或服务工作线程重启后也保留去重屏障。核验用的临时子标签页会关闭，主活动标签页保留供人工查看并在后续动作中安全复用。

## 点赞与评论通道

模型只保存 `like` 或 `comment` 建议，初态为 `draft`。宿主的自动点赞和自动评论开关默认关闭；保存开启后，每轮结束且宿主仍空闲时可自动执行本轮的一条对应建议。每日互动总额度默认为 3 次，可设 0–10，按 UTC+8 计算；未知结果也占额度。手动执行同样受开关、目标 UID 和额度约束。扩展本身不调度任务，也没有收藏、关注、投币或私信监听功能。

`interact` 在准备、点击和读取回执时都核对当前账号与视频地址。已点赞时不会再点击而取消点赞。评论编辑器必须为空，不能带已有正文或附件；填入最终正文后再次检查，按钮失效、正文变化、已有同文评论或页面有歧义时停止。真正提交前先持久保存去重记录，取消或写盘失败不能继续点击。

评论成功需要唯一匹配的作者、正文、真实评论 ID 和提交时间；作者证据不能由正文里的个人空间链接替代，嵌套回复或多个作者／正文不能误认。已确认评论可按保存的评论 ID 核验。点赞需确认当前页面已点赞状态。证据不足时返回 `unknown`，宿主仅允许 `verify_interaction` 只读核验，不能重发。重复互动 ID 不会再点击；同一 ID 改变动作、视频或正文也会拒绝。

DOM 依据：2026-10-23 只读检查了 B 站公开提供的 [动态首页脚本](https://s1.hdslb.com/bfs/static/2233-monorepo/dyn-home/static/js/index.c648f6cd.js)、[公开页头脚本](https://s1.hdslb.com/bfs/seed/laputa-header/bili-header.umd.js) 和 [opus 详情脚本](https://s1.hdslb.com/bfs/static/2233-monorepo/opus-detail/opus-detail.b4018a24e2dac1a617caaef36fe90cace65de744.js)。账号组件、编辑器、发布 DIV、动态时间和作者节点的固定选择器来自这些公开资源；未读取登录凭据，未使用真实账号做发布验收。页面改版或出现风控时需要人工检查，不能把离线测试通过当成真实发布已验证。

开发验证：在项目根目录运行 `node tests/test_bilibili_activity_extension.js`、`node tests/test_bilibili_activity_reader.js`、`node tests/test_bilibili_interaction_extension.js`、`node tests/test_bilibili_activity_ui.js` 及原点歌测试。测试仅使用模拟 Chrome API、固定响应和本地 DOM，不访问 B 站账号或真实按钮。真实登录、字幕可用性及页面控件仍需正常浏览器验收。
